# 《山海烽火》原创世界观与阵营设定

> **文档版本：** V1.0  
> **状态：** 概念设计稿，待玩法、美术与商标审查  
> **目标市场：** 中国大陆  
> **首发平台：** 微信小游戏（规划）  
> **技术基线：** Cocos Creator 4 + TypeScript  
> **项目定位：** 东方神话题材、轻量级 2D 即时战略（RTS）

---

## 1. 项目概述

### 1.1 核心定位

《山海烽火》是一款以东方神话、上古灾变和多阵营战争为背景的轻量级即时战略游戏。

玩家选择一个阵营，在短局制战场中采集资源、建设据点、训练部队、释放技能并争夺地图控制权。游戏以清晰易懂的 RTS 战斗为核心，逐步扩展单人战役、好友对战和原创内容。

**核心宣传语：**

> 山海封印已破，九州烽火再起。

### 1.2 产品目标

- 保留现有项目中经过验证的 RTS 基础系统和战斗模拟架构。
- 重做世界观、阵营、兵种、建筑、UI、美术、音频、关卡与文案。
- 不把原版《城邦争霸》的角色、建筑、图标、地图、动画或具体美术表达直接换色复用。
- 先完成一个高质量可玩关卡，再扩展完整战役和多人模式。
- 所有正式资源均建立来源、生成工具、授权与人工修改记录。

### 1.3 核心体验

1. **快速开局：** 玩家能在短时间内理解资源、建筑和出兵规则。
2. **据点争夺：** 控制城镇、资源点和战略通道，逐步扩大优势。
3. **兵种协同：** 步兵、远程、骑兵、辅助和攻城单位承担不同职责。
4. **阵营差异：** 三个可玩阵营拥有不同的战斗机制，而不是仅更换外观。
5. **技能决策：** 技能影响局势，但不能取代基础部队和经济运营。
6. **短局可重玩：** 单局目标明确，适合移动端碎片化体验。

## 2. 世界观

### 2.1 世界背景

天地初定之时，九州之间流动着一种被称为“玄息”的原初力量。山川、河流、草木与生灵都受到玄息滋养。

远古时期，先民在九州建立城邦，昆仑诸神维护天地秩序，大荒部族守护山川与异兽。三方并非始终和平，但共同维持着世界的基本平衡。

后来，一场被称为“天裂之劫”的灾变降临。九座镇世神鼎相继失去力量，山河出现裂隙，古老遗迹苏醒，异兽开始迁徙，部分地区被混沌侵蚀。

原有秩序随之崩溃：

- 人族王朝失去对边境的控制，诸侯和军镇各自为政。
- 昆仑神庭认为灾变源于凡间对玄息的滥用，开始收紧对九州的控制。
- 大荒妖盟认为人神两族长期侵占山川，借灾变之机争取领地与生存空间。
- 混沌势力从裂隙中扩散，侵蚀生灵和遗迹，成为各方共同面对的威胁。

三方围绕神鼎碎片、玄息矿脉、古代城池和战略要地展开战争。玩家将从一处边境据点起步，逐步参与九州争夺，并揭开天裂之劫的真相。

### 2.2 世界观基调

| 维度 | 设定 |
| --- | --- |
| 时代感 | 架空上古至古代王朝时期 |
| 氛围 | 苍凉、厚重、神秘、战争感 |
| 神话表达 | 山海异兽、古老祭祀、遗迹、神术 |
| 战争表达 | 城池、军阵、骑兵、弩兵、攻城器械 |
| 叙事方式 | 阵营立场冲突，不设置简单绝对善恶 |
| 视觉关键词 | 东方暗黑写实、青铜、玄铁、玉石、山川、风沙、雾气 |

### 2.3 原创性边界

《山海经》仅作为文化母题和灵感来源，不直接复制任何现成游戏的角色设计、地图布局、剧情表达或美术资源。

对传统神话名词和异兽的使用应进行独立设计。正式发行前，应对游戏名称、角色名称、标志、文案和美术表达进行商标及知识产权检索。

## 3. 世界地图与区域

世界暂分为九个主要区域。区域名称、地形和阵营归属均为初步设定，后续可根据关卡设计调整。

| 区域 | 地形特征 | 主要内容 |
| --- | --- | --- |
| 中州 | 平原、河流、古城 | 人族核心领地、粮食与人口 |
| 玄北 | 雪山、冰原、冻土 | 神庭遗迹、寒冷地形 |
| 苍南 | 密林、沼泽、山寨 | 妖盟部族、伏击路线 |
| 西漠 | 戈壁、峡谷、古道 | 商路、矿脉、遗迹 |
| 东海 | 海岸、岛屿、神殿 | 海上据点、古代祭坛 |
| 赤岭 | 火山、熔岩、矿山 | 金属资源、危险地形 |
| 云泽 | 山谷、湖泊、湿地 | 水路、村落、补给点 |
| 幽都 | 荒坟、古战场、地宫 | 混沌污染、地下遗迹 |
| 大荒 | 荒原、裂隙、远古废墟 | 高风险区域、章节终局 |

### 3.1 地图玩法原则

- 地形必须影响路线、视野或战术选择，不能只作为背景装饰。
- 每张地图至少设置一个可争夺的战略目标。
- 资源点、据点和出生区域应保持基本公平。
- 山地、河流、桥梁和峡谷应形成可读的战场通道。
- 环境危害应有明确预警和可理解的规则。

## 4. 可玩阵营

首发规划为 **3 个可玩阵营 + 1 个敌对势力**。三个阵营应共享基础 RTS 规则，但拥有不同的单位组合、技能和战术节奏。

### 4.1 九州人皇

**阵营理念：** 以人之力，重定九州。

人族由王朝军队、地方军镇和诸侯势力组成。其优势来自组织、军阵、工程和稳定的后勤体系。人族没有神族的天生神通，也没有妖族的异兽体魄，但能通过训练、装备和协同弥补差距。

**视觉识别：**

- 主色：朱红、暗金、玄铁。
- 材质：铁甲、皮革、青铜、漆木、织物。
- 建筑：城墙、箭楼、军营、粮仓、祭台。
- 轮廓：规整、厚重、强调盾牌和阵列。
- 设计关键词：秩序、军纪、工艺、守城、军阵。

#### 兵种规划

| 兵种类别 | 基础单位 | 进阶方向 | 战术职责 |
| --- | --- | --- | --- |
| 步兵 | 铁甲卫 | 玄甲卫 | 前排承伤、守点 |
| 远程 | 弩兵 | 神机弩手 | 稳定远程输出 |
| 骑兵 | 羽林骑 | 虎贲铁骑 | 冲锋、追击 |
| 辅助 | 军阵师 | 天策军师 | 增益、士气、阵型 |
| 攻城 | 投石车 | 破城巨弩 | 摧毁建筑、压制据点 |

#### 建筑规划

| 建筑 | 功能 |
| --- | --- |
| 镇国城 | 核心据点、失败保护目标 |
| 郡城 | 人口、资源或据点控制 |
| 军营 | 训练基础步兵与骑兵 |
| 神机坊 | 生产远程及攻城器械 |
| 镇灵台 | 产生玄息、解锁阵营技能 |
| 粮仓 | 提供军粮储备或人口支持 |

#### 阵营技能

| 技能 | 设计效果 | 使用场景 |
| --- | --- | --- |
| 铁壁军阵 | 一段时间内降低范围内友军受到的伤害 | 防守、守桥 |
| 战鼓振军 | 提升范围内友军攻击或士气 | 集中推进 |
| 万弩齐发 | 对指定区域进行远程打击 | 压制密集敌军 |
| 人皇御令 | 短时间强化全军作战能力 | 决战、反攻 |

**玩法定位：** 稳定、均衡、正面作战能力强，适合新手和偏好运营的玩家。

### 4.2 昆仑神庭

**阵营理念：** 天道不可违，万物归于序。

昆仑神庭由古老神祇、守界者和神庭军团组成。神庭认为天裂之劫源于九州对玄息的过度索取，只有重新掌控神鼎、恢复天地秩序，才能阻止世界继续崩坏。

神庭军团数量不占优势，但拥有强大的神术、控制能力和高价值单位。

**视觉识别：**

- 主色：玉白、霜蓝、天金。
- 材质：白玉、青铜、丝绸、半透明晶体。
- 建筑：高台、神殿、祭坛、悬空石构、符文石柱。
- 轮廓：修长、垂直、轻盈，强调仪式感。
- 设计关键词：秩序、神性、雷霆、寒霜、符文。

#### 兵种规划

| 兵种类别 | 基础单位 | 进阶方向 | 战术职责 |
| --- | --- | --- | --- |
| 步兵 | 天兵 | 玉甲天卫 | 精锐前排 |
| 远程 | 灵弓使 | 星辰射手 | 精准远程打击 |
| 骑兵 | 云骑 | 天马神骑 | 快速机动、突击 |
| 辅助 | 御灵师 | 雷法天师 | 治疗、控制、增益 |
| 攻城 | 符文傀儡 | 镇天神像 | 重型攻坚、区域压制 |

#### 建筑规划

| 建筑 | 功能 |
| --- | --- |
| 昆仑神宫 | 核心据点 |
| 灵台 | 人口或玄息补给 |
| 天兵殿 | 训练神庭军队 |
| 聚灵塔 | 玄息产出 |
| 镇界碑 | 防御、视野或区域控制 |
| 符文工坊 | 生产傀儡和特殊器械 |

#### 阵营技能

| 技能 | 设计效果 | 使用场景 |
| --- | --- | --- |
| 九霄落雷 | 对指定区域造成雷电伤害 | 打击密集敌军 |
| 寒天封灵 | 减速或短暂限制敌方单位 | 阻止冲锋、保护后排 |
| 天罡庇护 | 为友军提供护盾或减伤 | 保护精锐单位 |
| 天罚降世 | 召唤神像或神力攻击战场 | 关键团战 |

**玩法定位：** 高控制、高技能价值、单位成本较高，适合重视技能时机和战术调度的玩家。

### 4.3 九黎妖盟

**阵营理念：** 山川归荒，万灵自由。

九黎妖盟由大荒中的异兽部族、山林族群和古老祭司组成。他们拒绝人族王朝的领土秩序，也不接受神庭对玄息的垄断。妖盟希望夺回被占据的山川和生存空间。

妖盟擅长机动、突袭、召唤和持续作战，但防御工事与正面阵列相对薄弱。

**视觉识别：**

- 主色：苍绿、赤褐、古铜。
- 材质：木材、兽骨、皮革、石材、青铜。
- 建筑：山寨、兽穴、图腾、祭坛、木石围墙。
- 轮廓：不对称、粗犷、带有兽类特征。
- 设计关键词：野性、部族、异兽、图腾、山林。

#### 兵种规划

| 兵种类别 | 基础单位 | 进阶方向 | 战术职责 |
| --- | --- | --- | --- |
| 步兵 | 山魈战士 | 虎魄战将 | 近战突击 |
| 远程 | 毒羽妖 | 风翎妖卫 | 持续伤害、牵制 |
| 骑兵 | 狼骑兵 | 赤焰兽骑 | 高机动、追击 |
| 辅助 | 狐灵祭司 | 九尾灵巫 | 召唤、恢复、诅咒 |
| 攻城 | 巨角兽 | 山岳巨兽 | 冲击城门、破坏建筑 |

#### 建筑规划

| 建筑 | 功能 |
| --- | --- |
| 万妖寨 | 核心据点 |
| 妖族聚落 | 人口或基础资源 |
| 兽穴 | 训练异兽单位 |
| 血灵祭坛 | 玄息与妖术资源 |
| 图腾柱 | 区域增益或视野 |
| 猎场 | 提供军粮或特殊材料 |

#### 阵营技能

| 技能 | 设计效果 | 使用场景 |
| --- | --- | --- |
| 万兽狂怒 | 提升友军移动速度或攻击速度 | 突袭、追击 |
| 蚀骨毒雾 | 对区域内敌人造成持续伤害 | 阻断路线、消耗 |
| 妖魂召唤 | 临时召唤异兽参战 | 补充兵力、扰乱阵型 |
| 大荒兽潮 | 召唤巨兽冲击指定方向 | 突破防线、攻城 |

**玩法定位：** 高机动、强突袭、擅长扰乱和持续消耗，适合主动进攻型玩家。

## 5. 敌对势力：混沌

混沌不是普通国家，而是天裂之劫释放出的上古侵蚀力量。它会污染土地、扭曲生灵，并使古代遗迹失控。

首发版本中，混沌主要作为 AI 敌对势力和地图中立威胁，不作为玩家可选阵营。

### 5.1 视觉识别

- 主色：幽黑、暗紫、血红。
- 材质：腐化石材、裂纹骨甲、黑曜石、异化组织。
- 轮廓：不对称、扭曲、具有不稳定感。
- 特效：暗紫裂隙、黑雾、侵蚀纹路、局部红光。

### 5.2 单位规划

| 单位 | 战术职责 |
| --- | --- |
| 蚀魂兵 | 基础近战 |
| 幽冥射手 | 远程压制 |
| 冥骨兽骑 | 快速突袭 |
| 混沌巫使 | 诅咒、召唤 |
| 深渊巨兽 | 重型攻城与首领战 |

### 5.3 中立首领

可以从传统神话异兽中汲取灵感，例如混沌、饕餮、梼杌等，但应重新设计其外观、技能、背景和战斗行为，避免直接复制其他作品中的既有形象。

## 6. 阵营差异与平衡原则

| 维度 | 九州人皇 | 昆仑神庭 | 九黎妖盟 |
| --- | --- | --- | --- |
| 核心优势 | 均衡、军阵、工程 | 控制、技能、精锐 | 机动、突袭、召唤 |
| 防御 | 强 | 中 | 弱至中 |
| 爆发 | 中 | 强 | 中至强 |
| 机动 | 中 | 中 | 强 |
| 持续作战 | 强 | 中 | 强 |
| 控制 | 中 | 强 | 中 |
| 操作难度 | 低至中 | 中至高 | 中 |

以上是设计目标，不是最终数值。正式平衡需要通过统一地图、统一初始资源、固定随机种子和多组操作策略进行模拟测试。

### 6.1 平衡约束

- 不允许某一阵营在所有阶段都占优。
- 强力技能必须具有资源、冷却、范围或使用时机限制。
- 高机动单位应有明确的成本或生存弱点。
- 召唤单位应计入人口、持续时间或资源成本。
- 攻城单位需要受到近战突袭或地形限制。
- 每种主流战术都应至少存在一种可行反制方式。

## 7. 资源经济系统

建议沿用现有项目中成熟的资源管理框架，但重新定义资源名称、产出方式、用途和视觉表现。

| 资源 | 用途 | 视觉表现 |
| --- | --- | --- |
| 金铢 | 招募、建造、升级 | 古代金属钱币或金锭 |
| 玄息 | 释放阵营技能、特殊建筑 | 发光晶体、灵气纹路 |
| 军粮 | 人口、部队维护或军团规模 | 粮袋、谷物、粮仓 |

资源系统需要遵循以下原则：

1. 新手阶段尽量只暴露必要资源。
2. 资源产出和消耗应有清晰反馈。
3. 不能让经济操作频繁打断战斗。
4. 阵营差异应体现在资源使用方式，而不是增加过多难以理解的货币。
5. 经济系统应支持离线单机和未来服务器权威计算。

## 8. 单人战役规划

首发战役规划为三个阵营各八关，共 24 关。三条战役线从不同立场讲述同一场战争。

| 章节 | 九州人皇篇 | 昆仑神庭篇 | 九黎妖盟篇 |
| --- | --- | --- | --- |
| 第一章 | 烽火初起 | 昆仑惊变 | 大荒苏醒 |
| 第二章 | 收复边关 | 天门失守 | 万兽集结 |
| 第三章 | 河谷争夺 | 霜原之战 | 苍林复仇 |
| 第四章 | 赤岭攻坚 | 神鼎遗迹 | 赤焰山脉 |
| 第五章 | 三族交锋 | 九霄雷鸣 | 狂野军团 |
| 第六章 | 幽都迷雾 | 天道之争 | 幽谷血战 |
| 第七章 | 九州决战 | 混沌降世 | 万妖归心 |
| 第八章 | 人皇之路 | 重定天命 | 山海归荒 |

### 8.1 关卡目标类型

- 摧毁敌方核心据点。
- 在限定时间内守住城池。
- 占领并控制多个战略据点。
- 护送补给或特殊单位。
- 击败地图首领。
- 在资源受限条件下完成战斗。
- 与友军协同完成攻防目标。

每关应包含主目标、可选目标、难度评价和可解锁奖励。关卡布局、剧情和任务条件必须独立创作。

## 9. 美术方向规范（Art Bible）

### 9.1 总体风格

**东方暗黑写实，兼顾移动端可读性。**

目标不是追求纯写实电影画面，而是在有限屏幕和小尺寸单位下，保留清楚的轮廓、材质层次和阵营识别。

### 9.2 视角与构图

- 战场采用统一的斜俯视或等距视角。
- 建筑、单位和地面装饰必须遵守同一透视规则。
- 同一类单位应保持一致的视觉高度和占地尺寸。
- 主城必须有清晰的轮廓，缩小后仍能辨认阵营。
- 角色头部、武器和阵营标识不能被无关装饰遮挡。

### 9.3 阵营色彩

| 阵营 | 主色 | 辅色 | 材质关键词 |
| --- | --- | --- | --- |
| 九州人皇 | 朱红 | 暗金、玄铁 | 铁甲、漆木、青铜 |
| 昆仑神庭 | 玉白 | 霜蓝、天金 | 白玉、晶体、丝绸 |
| 九黎妖盟 | 苍绿 | 赤褐、古铜 | 兽骨、木材、皮革 |
| 混沌 | 幽黑 | 暗紫、血红 | 黑曜石、腐化组织 |

### 9.4 角色设计规范

每个单位需要提供：

- 正面或 3/4 角度角色设定图。
- 清晰的全身轮廓。
- 武器、护甲和阵营识别元素。
- 身高比例和占地尺寸。
- 颜色与材质说明。
- Idle、Walk、Attack、Hit、Death 等动作规划。
- 需要时提供不同方向的动作参考。

不要仅凭一张角色概念图直接制作全部动画。必须先验证角色在游戏镜头和实际缩放下是否清楚。

### 9.5 建筑设计规范

每座建筑需要提供：

- 统一角度的完整建筑图。
- 建筑占地和碰撞范围。
- 生产、升级或被攻击状态。
- 建筑等级变化方案。
- 阵营色彩和标志。
- 透明背景或明确的地面阴影规范。

### 9.6 UI 设计规范

- 使用青铜、玄铁、玉石和古纸作为材质参考。
- 优先保证按钮、资源数字和战斗信息可读。
- 不让装饰纹样干扰交互。
- 重要操作必须有明确状态反馈。
- 同一类按钮保持统一尺寸、圆角和图标语义。
- 所有文字由程序排版，不依赖 AI 在图片内生成文字。

### 9.7 明确禁止的视觉方向

- 不直接仿制《城邦争霸》的单位轮廓、建筑布局和 UI。
- 不复刻其他热门游戏的角色、技能图标和商标。
- 不混用不同视角、不同光源方向和不同材质体系。
- 不使用细节过多、缩小后无法辨认的单位设计。
- 不让 AI 直接把中文标题、数值或按钮文字绘制进正式 UI 图片。

## 10. AI 资源生产规范

### 10.1 生产原则

采用“人工设定 + AI 生成 + 人工筛选与修改 + 自动化处理 + 游戏内验收”的流程。

AI 生成图不能直接视为最终游戏资源。正式导入前应检查：

- 版权与服务商商业许可。
- 是否出现第三方角色、商标或明显临摹。
- 透明背景和边缘质量。
- 图片尺寸、比例和锚点。
- 角色结构、武器和肢体是否正确。
- 同一批次的风格一致性。
- 缩小到实际游戏尺寸后的可读性。

### 10.2 推荐工具分工

| 工具 | 主要用途 |
| --- | --- |
| ChatGPT 图像生成 | 概念设计、角色和建筑初稿、风格探索 |
| ComfyUI | 可复用工作流、参考图控制、批量处理 |
| Scenario | 游戏资产风格一致性与批量生成 |
| Photoshop / Photopea | 人工修图、边缘清理、合成 |
| Blender | 必要时制作辅助模型、统一视角和渲染 |
| Python + Pillow | 裁切、透明边缘检查、尺寸规范化 |
| OpenCV | 图像检测、批量预处理 |
| ElevenLabs 或其他授权音频工具 | 音效与环境音生成 |

具体服务的商用权限、生成内容使用范围和订阅要求，应以使用时的最新服务条款为准。

### 10.3 首批垂直切片资源

第一批不要追求数量，优先验证一关能否达到正式产品的美术质量。

| 类别 | 首批内容 |
| --- | --- |
| 世界观 | 九州世界地图概念图 |
| 阵营 | 三个可玩阵营和混沌势力设定板 |
| 建筑 | 四个阵营主城概念图 |
| 步兵 | 三个可玩阵营基础步兵 |
| 骑兵 | 三个可玩阵营基础骑兵 |
| 远程 | 三个可玩阵营基础远程单位 |
| 地图 | 中州平原、昆仑雪山、苍南森林 |
| UI | 主菜单、战斗 HUD |
| 图标 | 三种资源、阵营徽章、首批技能图标 |
| 动画 | 至少一个步兵的完整基础动作测试 |
| 音频 | UI 点击、脚步、攻击、受击、环境氛围 |

### 10.4 动画生产策略

动画是 AI 资产生产中最需要控制质量的部分。

建议先选一个基础步兵做完整测试：

| 动作 | 初步帧数规划 |
| --- | --- |
| Idle | 6～8 |
| Walk | 8～12 |
| Run | 8～12 |
| Attack | 8～12 |
| Hit | 3～6 |
| Death | 8～12 |

帧数是制作预算参考，不是最终规格。应根据实际帧率、动作速度和引擎性能调整。

优先评估骨骼动画、序列帧动画和混合方案。不要在没有验证的情况下，为每个单位、每个方向都制作大量独立帧。

## 11. Cocos Creator 资源接入规范

项目当前技术基线为 Cocos Creator 4 + TypeScript。正式接入时，应以项目实际使用的引擎版本和 API 为准。

### 11.1 资源目录建议

```text
game/assets/
├── art/
│   ├── factions/
│   │   ├── human/
│   │   ├── celestial/
│   │   ├── beast/
│   │   └── chaos/
│   ├── units/
│   │   ├── infantry/
│   │   ├── ranged/
│   │   ├── cavalry/
│   │   ├── support/
│   │   └── siege/
│   ├── buildings/
│   ├── terrain/
│   ├── effects/
│   └── ui/
├── animation/
│   ├── units/
│   └── effects/
├── audio/
│   ├── bgm/
│   ├── sfx/
│   └── ambience/
└── atlases/
```

### 11.2 命名规则

建议采用统一的小写英文、下划线和稳定 ID：

```text
faction_human_castle_lv1.png
unit_human_infantry_iron_guard_idle_01.png
unit_celestial_archer_star_shooter_attack_01.png
unit_beast_cavalry_wolf_rider_run_01.png
building_human_barracks_lv1.png
icon_skill_human_iron_wall.png
icon_resource_mystic_energy.png
```

资源 ID 一旦被配置文件或代码引用，不应随意修改。替换资源时优先保持稳定 ID，减少代码和 Prefab 改动。

### 11.3 SpriteFrame 与图集

Cocos Creator 4.0 官方文档说明，SpriteFrame 管理图像裁剪等信息，并由 Sprite 组件使用；图像导入后可创建对应 SpriteFrame。

- Cocos Creator 4.0：SpriteFrame 资源 (https://docs.cocos.com/creator/4.0/manual/zh/asset/sprite-frame.html)
- Cocos Creator 4.0：Asset Bundle (https://docs.cocos.com/creator/4.0/manual/zh/asset/bundle.html)
- Cocos Creator 4.0：动态加载资源 (https://docs.cocos.com/creator/4.0/manual/zh/asset/dynamic-load-resources.html)

接入原则：

1. 同一角色或同一功能模块的资源按需组织。
2. UI 图标、单位动画、建筑和地图资源分开管理。
3. 图集尺寸应根据目标设备、纹理限制和实际包体测试确定。
4. 高频共享资源避免在多个 Bundle 中重复打包。
5. 对不再使用的资源建立清理流程。
6. 不要仅为了图集数量而把所有资源塞进一张大图。

### 11.4 资源替换策略

不要直接覆盖旧资源目录。建议：

1. 新建原创资源目录。
2. 建立旧资源 ID 到新资源 ID 的映射。
3. 先替换一个测试关卡。
4. 检查 Prefab、AnimationClip、SpriteFrame、配置和脚本引用。
5. 验证构建结果。
6. 确认无引用后，再清理旧资源。

## 13. 开发阶段与验收标准

### 阶段 A：美术方向验证

交付：

- 世界观与阵营设定确认。
- 三个阵营主城概念图。
- 三个阵营基础步兵概念图。
- 一张战场概念图。
- 一套 UI 风格稿。

验收：

- 三个阵营缩小后仍能区分。
- 角色和建筑视角统一。
- 颜色和材质符合 Art Bible。
- 不存在明显的第三方作品临摹。
- 美术方向适合当前屏幕比例和单位尺寸。

### 阶段 B：垂直切片

交付：

- 一个完整可玩关卡。
- 三个阵营至少一套基础单位。
- 主城、军营、资源建筑。
- 基础技能和 HUD。
- 单位待机、移动、攻击、受击和死亡动画。
- 基础战斗音效。

验收：

- 游戏能完整开始、战斗和结束。
- 单位动画不会明显跳帧或变形。
- 资源加载和释放正常。
- 不影响现有战斗模拟结果。
- Web 或目标平台构建成功。

### 阶段 C：完整资源替换

交付：

- 全部正式单位、建筑、图标和地图资源。
- 全部 UI、特效、音频和战役插画。
- 完整资源映射表。
- 资源来源记录。
- 资源校验报告。

验收：

- 不再引用未授权的原版美术和音频。
- 所有正式资源均通过尺寸、透明通道和命名检查。
- 所有关卡均可加载。
- 不存在缺图、错图、引用丢失和动画缺帧。
- 目标平台包体、内存和帧率满足项目设定。

### 阶段 D：原创产品化

交付：

- 原创战役内容。
- 阵营平衡调整。
- 新手引导。
- 音频和视觉反馈完善。
- 平台适配、隐私和上架材料。
- 商业化方案及运营计划。
